# 统一模型来源、网关管理与智能路由设计

日期：2026-10-26  
状态：已确认设计方向，待实施计划

## 1. 目标与边界

把 claude-web 现有的供应商、Claude 账号、Gemini 网页、WorkBuddy、内嵌网关和 sidecar 收进一个统一的来源管理台，并内置更多反代引擎、免费模型来源、隐私保护、插件、同步、远程共享和智能路由。

核心边界：

- **网关只管理来源**：安装、登录、账号、模型目录、额度、隐私、共享和路由。
- **对话只负责调用**：模型选择和真实请求始终发生在当前对话工作台。网关不包含消息列表、聊天输入框或第二套聊天页面。
- 保留所有已有供应商、账号、模型映射、Gemini 网页和 WorkBuddy，不要求用户重新配置。
- 免费模型可单独选择，也可通过用户明确选择的智能路由使用。
- 所有渠道和托管引擎均纳入范围；不以逐条风险勾选作为安装前置条件，但必须清楚展示隐私、费用、状态与共享边界。

## 2. 已确认的交互方向

### 2.1 A+B 管理首页

采用卡片仪表盘与分类筛选的组合：

- 顶部：标题、搜索、「添加来源」、隐私和共享入口。
- 左侧只是来源筛选：全部、免费、订阅、API 供应商、本机引擎、需要处理。
- 右侧是来源卡片：图标、状态、模型数、账号数、额度和主操作。
- 顶部汇总可用来源、可用模型和剩余额度。
- 手机端左侧筛选变为横向滚动，卡片单列。
- 卡片选中只使用轻微边框/背景反馈，不使用左侧高亮条、发光选中条或夸张位移。

### 2.2 移除重叠 Tabs 和“高级设置”

| 旧入口 | 新位置 |
| --- | --- |
| 总览 | 新首页 |
| 账号 | 对应来源详情的账号模块 |
| 任务 | 对应账号或来源详情的后台任务模块 |
| 路由 | 独立“智能路由”虚拟来源，以及来源详情中的映射与顺序 |
| 密钥 | 共享抽屉 |
| 日志 | 活动视图及来源详情中的过滤日志 |
| 设置 | 拆回来源、隐私和共享，不再设置总“高级”开关 |

所有旧功能必须能在新结构到达，不以重构为名删除能力。

### 2.3 唯一添加入口

「添加来源」打开同一向导，首层为：

1. 免费使用：免 Key、官方免费 Key、IDE/订阅免费额度。
2. 登录账号：Claude、Gemini 网页、WorkBuddy、Codex、Cline 等。
3. 填写 API 地址：官方、中转及 Anthropic/OpenAI/Gemini 兼容端点。

下方提供搜索和完整目录。每种来源只展示必要步骤；完成后显示“已可用”，不提供“去聊天”或“使用”按钮。

### 2.4 对话内模型选择

- 已配置模型自动进入当前对话的模型菜单，按免费、订阅、API、本机和智能路由分组。
- 菜单底部提供「管理来源」。
- 缺少来源时可在当前对话打开轻量添加面板，完成后原地返回，保留草稿、消息、滚动位置。
- 失败时提供重试、换模型、管理来源；除用户选择的智能路由外，不自动换来源。

## 3. 总体架构

### 3.1 ChannelDriver：来源适配

每种来源实现统一驱动，负责：

- 安装、升级、启动、停止（如适用）。
- 登录、Cookie、Key、OAuth 和凭据保存。
- 模型目录与能力识别。
- 健康、额度、冷却和错误。
- 转换为对话可使用的 Provider 或 Upstream。

覆盖：

- 现有 Gemini 网页、WorkBuddy、Claude 账号、供应商和网关分组。
- CLIProxyAPI、Magpie。
- 调研清单中的免 Key、官方免费 Key、IDE/订阅渠道。
- 官方供应商、中转和自定义兼容端点。

驱动注册表替代围绕三个 `UpstreamKind` 散落的 switch。对话不直接依赖驱动，只继续消费 Provider/Upstream。

### 3.2 EngineManager：托管引擎

扩展现有 `upstreams/sidecar.ts` 与 `sidecars.json`，统一管理：

- 平台清单、版本锁定、下载、SHA-256 校验。
- 安装、升级、失败回滚。
- 端口分配、健康检查、异常退出、进程树停止。
- 引擎日志和本机管理密钥。
- 默认只监听 `127.0.0.1`；管理口不随共享开放。

子进程显式使用 `windowsHide: true`。

### 3.3 统一调用边界

```text
网关管理：
ChannelDriver → 安装/登录 → 模型与额度 → Provider/Upstream

普通模型调用：
当前对话 → Provider/Upstream → 协议转换 → PrivacyPipeline → 上游
         ← 消息与工具解析 ← 流式还原 ← 上游响应

智能路由调用：
当前对话的虚拟模型 → 候选过滤 → 策略选择 → 上述同一条调用链
```

现有 `gateway/` 继续负责协议转换、鉴权、缓存、模型映射和请求链；`upstreams/` 继续负责账号、sidecar、额度和已有渠道。

## 4. 隐私与安全

### 4.1 PrivacyPipeline

在请求离开 claude-web 前统一处理，响应返回时还原：

- 密钥：API Key、私钥、JWT、密码、Token、配置敏感字段。
- 个人信息：邮箱、手机号、证件、银行卡及可配置类型。
- 自定义内容：人名、项目代号、主机名、前缀和正则。
- 每类动作：脱敏、提醒、拦截。
- 白名单：允许指定值原样发送。
- 本机/局域网上游可按来源跳过。
- 预览工具显示厂商将收到的内容，不保存预览文本。

占位符形如 `{{API_KEY_a1b2c3d4}}`，同一安装内对同一值保持稳定，尽量维持提示缓存。原值映射只保存在进程内存，重启后重建。

必须支持：

- 流式文本和工具参数还原。
- 跨 chunk 的占位符缓冲。
- JSON 转义与有限占位符变体。
- 签名 thinking、加密推理、模型/工具 ID 原样保留。
- 图片 OCR 不作脱敏承诺。

需要模型理解的秘密不能声称“脱敏后仍可推理”。隐私功能开启但管道不可用时请求失败，并明确说明未发送；不得裸发降级。

### 4.2 日志、遥测与诊断

- 默认记录来源、模型、状态、耗时、Token、缓存、错误类别和脱敏命中数。
- 请求/响应正文默认不保存；临时调试记录也必须先脱敏。
- 隐私记录只保存类型、长度、占位符及脱敏后的上下文，不保存原值。
- 上游错误和诊断导出统一再次脱敏。
- 外部遥测/导出按目标单独配置，明确发送范围。
- 日志和隐私记录有保留期限及清理入口。

### 4.3 凭据、插件和远程目录

- 凭据沿用 claude-web 加密保存，协议和 UI 只给打码值。
- 声明式驱动只含模型、端点、认证和能力数据，不执行代码。
- 可执行插件在独立进程运行，具有权限声明、超时、输出限制、网络与文件权限。
- 远程模型目录只分发数据并验证签名，不能下发可执行代码。
- 远程目录更新不得覆盖用户自定义、重新启用用户关闭项或恢复用户删除项。

## 5. 协议、模型目录与兼容性

### 5.1 鉴权与地址

新增 `Provider.authStyle: 'bearer' | 'x-api-key' | 'both'`，同步用于：

- 会话环境映射。
- 模型列表探测。
- 网关协议翻译。
- 供应商编辑表单。

新字段加入 meta 清理表。统一规范化 base URL，修复手动填写 `/v1` 后出现 `/v1/v1/messages` 的问题。

### 5.2 模型能力

统一记录：上下文、最大输出、工具、图片、思考、流式、价格、免费和可能训练。能力来源分为厂商声明、实际探测和用户覆盖。

保留三家族模型映射、后台小模型映射、子代理别名规则。增加：

- 文本工具调用方言救援；无法解析则当前请求失败，不输出乱码。
- 记录来源级不支持 tools、忽略 reasoning、拒绝缓存字段等兼容结果。
- 工具、上下文和思考能力不满足时，智能路由不得把该模型列为候选。

### 5.3 目录更新

采用内置基线、签名远程数据和实时上游目录三层：

- 内置基线保证离线可用。
- 远程目录负责新增、改名、下线和能力修正。
- 实时 `/models` 或驱动目录补充实际上游模型。
- 更新失败回退最近可用目录。
- 已下线模型标为不可用，不悄悄换成其他模型。

## 6. 免费模型与渠道

免费来源目录覆盖调研中的可用项，并按当前真实状态维护：

- 免 Key 公共池。
- 用户自带 Key 的官方免费层。
- IDE、订阅和账号渠道。
- 已有 Gemini 网页和 WorkBuddy。

免费标签只表示当前价格/渠道属性，不暗示永久可用、绝对隐私或无限额度。可能记录或训练的模型显示对应标签。

每个驱动必须完成模型发现、真实调用和错误展示，不能只添加一张静态卡片。免费来源失效后显示状态，不自动改名或替换。

## 7. 智能路由

### 7.1 用户可见形式

智能路由是模型菜单中的虚拟模型，不是暗中改变普通模型的行为。内置：

- 自动：综合能力、可用性、额度、速度和成本。
- 免费优先：只使用免费候选，全部不可用时停止。
- 性能优先：优先速度、稳定性和上下文。
- 能力优先：优先模型能力和工具支持。
- 自定义路由：自然语言规则、条件列表和优先级排序。

网关首页显示“智能路由”来源卡片。详情页配置策略、候选来源、规则、预算和切换行为，并显示当前策略、可用候选和今日切换次数。

### 7.2 候选过滤与排序

1. 根据任务判断工具、图片、上下文、思考和结构化输出要求。
2. 过滤不满足硬要求、未启用、不允许路由或已知不可用的模型。
3. 按策略排序：免费与额度、近期成功率、延迟、冷却、能力、用户优先级和成本上限。
4. 同一对话尽量保持模型亲和，保住上下文、工具格式和缓存。
5. 确实切换时记录原因，并处理工具方言、思考块和能力差异。

路由决策和实际命中模型必须可查看，不能把实际模型伪装成其他模型。

### 7.3 请求失败与切换

- 请求前已知模型不可用，可直接选择下一个候选。
- 尚未向上游产生有效输出、且没有执行工具时，可按策略尝试下一个候选。
- 已开始流出正文后，默认不暗中重放到另一个模型，避免拼接回答。
- 工具已经执行后失败，不自动重放整轮，避免重复副作用。
- 用户可配置是否允许失败切换、最大尝试次数、免费转付费和预算。
- 免费优先永不自动转付费；涉及付费的策略必须有明确付费许可和预算。

### 7.4 隐私与额度

- 只使用用户已启用且允许路由的来源。
- 隐私规则按最终来源执行；本机跳过规则不得错误继承到云端。
- 路由候选、决策原因、尝试和实际模型进入日志。
- 自动路由不是绕过账号并发、每日限制或共享密钥权限的途径。

## 8. 同步与远程共享

- 配置备份/恢复：来源设置、账号引用、模型映射、隐私和路由规则。
- 凭据与隐私配置使用独立口令加密同步。
- 不同步本机进程状态、临时冷却和绝对路径。
- 多设备按配置项合并，不以最后写入覆盖全部凭据。
- 远程共享使用独立调用密钥，支持来源/模型权限、并发和额度。
- 远程请求经过同一隐私、日志、协议和路由边界。
- 管理接口始终与共享调用接口分离。

## 9. 错误处理

- 安装失败：展示下载、校验或平台原因，支持重试和日志。
- 登录过期：来源进入“需要处理”，提供重新登录。
- 429/额度耗尽：展示已知重置时间；未知时不编造数字。
- 模型失败：普通模型提供重试/换模型/管理来源；智能路由按策略处理。
- 协议错误：一句人话概括，附脱敏后的技术详情。
- 健康检查优先模型列表或轻量探测；真实生成探测须明确标识。
- 模型列表可拉取不等于对话可用，状态不得混淆。

## 12. 测试与验收

### 单元与契约

- 所有驱动运行统一契约：目录、认证、状态、错误、能力。
- 目录合并不覆盖用户设置。
- URL 与三种鉴权方式覆盖 `/v1`、尾斜杠和双头拒绝。
- 隐私检测、白名单、拦截、中文内容和自定义规则。
- 流式跨 chunk、工具参数、JSON 转义和占位符变体。
- 隐私组件故障时零请求发出。
- 日志、错误和诊断不含原值。
- 路由硬条件过滤、亲和、付费边界和失败切换限制。

### 集成

- 假 Anthropic/OpenAI/Gemini 上游验证工具、图片、思考、流式和缓存。
- 假安装包/进程覆盖下载校验、升级回滚和异常退出。
- 旧 Gemini 网页、WorkBuddy 和供应商迁移后配置不变。
- 普通免费模型失败不调用第二来源。
- 智能路由只尝试允许的候选，不重复执行工具。
- 远程共享不能访问未授权模型或管理接口。

### 端到端与 UI

- 空状态添加来源后，回当前对话选模型并发送。
- 旧来源无丢失、模型菜单不重复。
- 无高级设置和重叠 Tabs，旧功能均可到达。
- 网关开关不卸载对话、终端和右侧面板。
- 手机筛选、详情返回、向导、隐私和路由配置。
- 智能路由在对话中显示虚拟模型与实际命中模型。
- 执行 `npm run typecheck`、`npm test`、`npm run build:all`、`npm run e2e`、`node scripts/ui-smoke.cjs`，并通过 i18n 与 wording 检查。

## 13. 明确禁止的行为

- 把聊天搬进网关。
- 删除已有 Gemini 网页、WorkBuddy 或供应商。
- 普通模型在未选择智能路由时暗中换来源或转付费。
- 智能路由在正文已输出或工具已执行后默认重放整轮。
- 用“免费”暗示永久、无限或绝对隐私。
- 让目录、插件、同步或日志导出绕过隐私与权限边界。
- 用“模型列表成功”冒充“真实对话成功”。

## 14. 浏览器：ego lite 收尾（2026-10-26 补充）

ego lite 作为 Agent 第一浏览器已经在 main（5614f2e、e078b74），并入本分支后与统一来源一起测试和发布。补两件：

### 14.1 `ego_browser` 走服务端权限闸

- 现在问不问由各 Agent 自己决定：Claude 默认模式会问；Codex、ACP 等按它们自己的审批设置，可能直接运行带着用户登录的脚本。
- 改为服务端统一询问：**除「完全放开」外每次都问，不分 Agent**（见 14.4）。复用 `site-gate.ts` 的 `gate.ask`，权限卡沿用现有的 ego 卡样式（标题带脚本里的第一个网址、完整脚本代码块），按钮只有「允许一次 / 拒绝」，不提供「总是允许」。
- 为避免 Claude 上出现两张卡，`ego_browser` 加入 `webAllowedTools`，只保留服务端这一张。
- 拒绝或超时：脚本不运行，返回明确的「用户拒绝了」，不触发退回内置浏览器。
- 没有 gate（单元测试、CLI）时与内置浏览器一致：不问。

### 14.4 「完全放开」= 什么都不问（用户 2026-10-26 决定）

- 对话处于「完全放开」（bypassPermissions）时，服务端自己弹的询问一律不弹、直接放行：内置浏览器的网站与脚本（`browser_eval`）、`ego_browser` 脚本、操控电脑的 `request_access`，以及以后新增的任何服务端询问。
- 其它权限模式行为不变：脚本每次问，网站按允许列表问，操控电脑每次问。
- 这是用户明确的取舍：操控电脑原本特意不看模式；改后「完全放开」的对话可直接控制任意应用。设置和模式说明里如实写明。
- 测试：每个服务端询问在 5 种其它模式下照旧，在「完全放开」下零张卡、动作照常执行。

### 14.2 内置浏览器截图在我们的内核上能被模型看到

- ccb 会把 MCP 工具藏到 `ExecuteExtraTool` 后面，结果被转成一段 JSON 文本，截图变成 base64 文字。
- 所有会返回图片的内置工具加 `_meta: {'anthropic/alwaysLoad': true}`：`browser_screenshot`、`browser_computer`，以及其它 MCP 服务器里同类出图工具（实施时逐个清点：预览、操控电脑等）。只给出图的工具加，不全部加，避免每轮工具列表变长。
- 官方内核本来就正常，不受影响。
