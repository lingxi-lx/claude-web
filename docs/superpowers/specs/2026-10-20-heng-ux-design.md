# 对照 heng1234/claude-web 的体验优化（阶段 E，2026-10-20）

对照仓库：<https://github.com/heng1234/claude-web>（Python + FastAPI + 原生 JS，Apache-2.0，2.4.4）。
只做设计参考，不复制其代码；我们的实现仍然在 Node / React 这套结构里。

## 结论

两边解决的是同一件事，方向不同：它把「普通聊天」和「代码工作区」做成两套界面，我们的做法是一个工作台
（对话 + 窗格 + 分组 + 右侧面板），默认就把项目、分支、运行状态放在一起。因此它的一些「分层」不是我们缺的
功能，而是两种产品形态。真正值得补的是**对话里的代码块可以直接运行**：它做成了「确认后本机执行」，我们原来只能
让 agent 去跑或复制到终端。

这次落地：

- **代码块运行**（`server/src/tools/run-code.ts` + `chat/CodeBlock.tsx`）：Bash / sh / zsh / shell / cmd / PowerShell /
  Python / Node 的代码块在**对话视图**里多一个「运行」按钮；点击先确认（会以用户身份在本机执行），服务端在
  **该对话的目录**执行，30 秒超时、输出上限 64 KB，超出就杀进程树并标记；结果显示在代码块下面（stdout、stderr、
  退出码、耗时），可收起。工具卡、子代理详情、旁聊里的代码块不显示按钮（`CodeRunCtx` 只由对话正文提供）。
- **只有本机窗口能运行**：`code.run` 在 hub 里走 `localWindowOnly`，手机 / 远程设备 / 联邦 peer 都不能调用；不经过
  agent 的权限系统，因为这是用户自己的操作，不是模型发起的工具调用。
- **会话目录**：优先用运行中会话的 `info.cwd`，其次用前端传来的 `cwd`；不合法就退回服务进程目录。前端不会
  自己拼 shell 命令。

## 风险与边界

- 代码块运行是**本机任意代码执行**：确认框是唯一闸门，且只对本机桌面窗口开放；远程 / 手机 / peer 直接拒绝。
- 超时会杀进程树（Windows `taskkill /T /F`，其它平台 `SIGKILL`）；输出按字节计，超过上限先截断再杀。
- 运行的是代码块的**完整文本**（不受折叠影响），语言只认白名单；未知语言报「不能直接运行」，不回退到 shell。
- 不把运行历史写进会话记录（它是一次本地操作，不是对话内容）；终端里仍可用 `npm run dev` / 窗格里的终端做长任务。
