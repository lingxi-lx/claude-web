# 首次使用：接一个模型 / Agent 检测（2026-09-30）

- **没有 Claude 订阅的人是默认用户**：首次引导第一步是「接一个模型」（`features/providers/QuickConnect.tsx`，纯逻辑 `quick.ts` + 测试）：选来源（中转站 / DeepSeek / Kimi / 智谱 / 通义 / 硅基流动 / OpenRouter / Gemini，`PRESETS`；厂商预设都是官方文档的 OpenAI 兼容地址，都有 `/models`）→ 中转站填地址（`cleanBase()`：补 https（本机 / 局域网补 http）、去掉粘进来的 `/chat/completions` `/messages`）→ 粘 Key → 连接。先 `providers.probe {listOnly:true}` 只读模型列表（不花 token），`quickPlan()` 按列表定格式和模型：中转站「自动」= 列表里有 Claude 模型就 Claude 格式（`anthropicBase()` 去掉 `/v1`，`modelMap` 三个家族都填上最新的那个——CLI 后台的 haiku 调用在没有那个确切 id 的中转上会失败——默认 sonnet），否则 OpenAI 格式；Bearer 列表失败时再按 Anthropic 头问一次；然后带着这个 plan 真跑一次 `providers.probe`（OpenAI 型一条短请求，Claude 型一次 CLI `-p`，被拒自动切官方二进制 `chat.switched`）；通过就 `providers.upsert`（`uniqueName`，中转站用主机名命名）并在需要时设成 `defaultProviderId`。失败的话 `explainProbe()` 说人话（Key 不对 / 余额 / 地址不对 / 连不上 / 不是 https / 模型用不了），原文在 tooltip；模型列表通了但测试没过可以「仍然保存」。「用 Claude 账号登录」（`claude auth login` 进终端）是次要链接。
- **模型挑选是共享纯函数**（`server/src/models/catalog.ts`，web 经 `@catalog`）：`pickChatModel()` 按 `CHAT_MODEL_PREFERENCE`（Claude sonnet → opus → gpt-5 → deepseek → kimi-k2 → glm → qwen coder…）取每组里最新的（`modelVersion()`：1–2 位数字，日期 / 尺寸不算），排除 embedding / 图像 / 语音等（`isChatModel`）；`claudeFamilyMap()`。服务端也用它：`providers.probe` 的 OpenAI 型测试模型、`providerEnv` 的 openai / gemini 家族兜底（以前是 `models[0]`，列表按字母排序，第一个常是 `dall-e-3` / embedding）。
- **「接一个模型」对话框**（`features/providers/ConnectModel.tsx`：`connectModel({reason})` 返回 Promise<Provider|null>，`ConnectModelHost` 挂在 App，`.dialog-bg` 所以在设置页之上、不被 inert）：`start`（首页提示）/ `send`（欢迎页发送时 Claude 账号确定未登录——`welcome-provider.ts` 的 `needsModel()`——接好后这条消息直接发出去，关掉对话框字留着）/ `session`（已有对话报「Not logged in · Please run /login」：StatusStrip 的 `data-err="no-login"` 给「接一个模型」= `session.setProvider` + `retryLast`，和「用 Claude 账号登录」；重试按钮不给，重试只会同样失败）/ `settings`（设置 → 供应商「快速添加」、账号与登录的「接一个模型」）。有已添加的供应商时顶上一排「用已添加的」一键选。新接的供应商在 Claude 账号没登录、也没有可用的默认供应商时自动设为默认（完整表单的保存同一规则）。
- **欢迎页的供应商跟着走**（`welcome-provider.ts` 的 `welcomeProvider()`）：用户没在模型菜单里选过时，上次用的（还可用）→ 默认供应商 → Claude 账号；**账号确定未登录且有可用供应商时永远不选账号**。设置、登录检查、供应商列表都在首次渲染之后才到，所以是 effect 里一直重算（`providerPicked` 之后才停），首次引导里接好的供应商立刻出现在芯片上。
- `claude auth status` 在 `~/.claude/settings.json` 的 `env` 里有 `ANTHROPIC_AUTH_TOKEN`（或进程 env 有 `ANTHROPIC_API_KEY`）时报 `loggedIn: true`（2026-09-30 用 ccb 实测），所以用 settings.json 配中转的老用户不会被拦。
- **Agent 检测**（`server/src/agents/locate.ts`）：从开始菜单 / Finder 启动的应用只有登录那一刻的 PATH，fnm 的 PATH 只在 shell 配置里、`uv tool` 的 bin 常不在 PATH。① `refreshProcessPath()`：把 Windows 注册表里**现在的** PATH（HKLM + HKCU，展开 `%VAR%`）和常见安装目录（`%APPDATA%\npm`、nvm4w / Program Files\nodejs、fnm 默认别名、pnpm、Volta、bun、WinGet Links、scoop、`~/.local/bin`、cargo、`~/.opencode/bin`；mac/Linux 的 Homebrew、nvm 最新版、fnm、mise/asdf…）里**存在的**追加到本进程 `PATH` 末尾（用户自己的顺序优先）；启动时一次、30 s 内复用，`agents.list {refresh:true}`（「重新检测」）强制。之后所有 spawn、终端面板、`npm i -g` 都看得到。② **Codex 桌面版 / IDE 扩展自带的 codex**（`findBundled('codex')`，取 mtime 最新）：Windows 商店版 Codex 把 CLI 拷到 `%LOCALAPPDATA%\OpenAI\Codex\bin\codex.exe`，新版本在 `bin\<hash>\codex.exe`（WindowsApps 里的那份外部起不了）；IDE 扩展在 `~/.vscode|.cursor|.windsurf/extensions/openai.chatgpt-*/bin/<windows-x86_64|macos-aarch64|…>/codex[.exe]`；mac 桌面版猜的是 `Codex.app/Contents/Resources/codex`（未实测）。本机实测桌面版的 codex.exe `app-server` 能正常 initialize。只在用户没设命令、PATH 里没有时用；`launch()` 也换成这个文件（会话能起），`login` 命令写成带引号的绝对路径（终端里同样找不到 `codex`）。③ **找到了就算装了**：`--version` 失败 / 超时（30 s）不再报「未安装」，而是 `installed:true` + `probeError`（`versionError()` 取 `Error:` 那一行，跳过 Node 打印的源码行和堆栈）；没找到时 `probeError` 说「PATH 里没有 X」；安装命令要的 npm / uv 也没有时 `installNeeds`（卡片上「下载 Node.js」+ 提示）。`AgentInfo` 新增 `path / from / probeError / installNeeds`。`AgentRegistry` 的定位器可注入（`AgentLocator`），`registry-probe.test.ts` 不依赖本机装了什么。
- 本机验证：假的 OpenAI 兼容中转（只认一个测试 key，`/v1/models` + 流式 `/chat/completions`）+ 临时 HOME 起 server：首次引导填错 Key 是「API Key 不对…」、填对后芯片立刻变成这个供应商、发消息拿到回复；删掉供应商后在欢迎页发送 → 「先接一个模型」→ 接好后消息自动发出；账号未登录的对话 → 「接一个模型」→ 换供应商并重试成功。PATH 只剩 System32 起 server，`agents.list` 仍找到 nvm4w 里的 codex / gemini / opencode。
- ui-smoke：引导第一步断言快速连接在位（预设、Key、连接）且没有「添加供应商 / 在终端登录」；冷启动发送在没登录也没供应商时断言弹「先接一个模型」、字还在、没开对话，然后用 `srvReq` 加一个指向 `127.0.0.1:9` 的供应商、点「用已添加的」让消息发出，结束后删掉它（后面的检查默认芯片是账号）。
