# 手机在外面也能连（2026-10-01）

spec：`docs/superpowers/specs/2026-10-01-remote-anywhere-design.md`（含实测结果）。手机不在家里 Wi-Fi 时也能用完整界面，不装 App、不注册、项目不运营服务器：公共 MQTT 牵线，能直连（WebRTC）就直连，不通就在 MQTT 上慢速转发。

- **结构**：
  - `server/src/remote/anywhere/core/`：电脑和手机壳共用（web 里是 `@anywhere` 别名），只用 Web 标准 API（不 import `node:*`，同目录 import 带 `.js`）。`keys.ts` 派生频道和密钥，`envelope.ts` 封牵线信封，`mqtt.ts` 是 broker 池（`Brokers`，同一条消息发给所有连上的），`lists.ts` 是 broker / STUN 列表的校验，`signal.ts` 是一个房间的牵线频道，`dial.ts`（手机）/ `accept.ts`（电脑）是握手（hello → ack → offer / answer / cand，`nodirect`、`relay`；协议表在 dial.ts 开头；直连没成、改走慢速转发时 `DialResult.directWhy` 说为什么——2026-10-09 CI 的 Ubuntu 上「直连」那条测试偶发退回转发，本机 Windows 复现不出来，测试失败时会把它打出来），`p2p-link.ts` 直连、`relay-link.ts` 慢速转发（kind 表是跨版本协议：手机上的壳和电脑上的版本不同，未知 kind 直接断开），`mux.ts` 把一条通道分成多个 WebSocket / HTTP 流（帧表在文件开头，电脑回的 `WS_OPEN` = 手机的 onopen）。
  - `service.ts`（`AnywhereService`）：远程访问在跑且 `remote.anywhere` 不是 false 时启动；每台已配对设备一个房间，配对码有效期内再加一个配对房间（码用掉 / 次数用完就不再回应，新码顶替旧码，到期删掉）；吊销 = 退订 + 这台设备的所有通道立刻断。状态在 `remote.status.anywhere`（`recent` 最近 20 次只在内存）。broker 的 WSS 走本进程的网络代理（`proxyAgentFor`），直连的 UDP 不走。node-datachannel 第一次用到才加载（`rtc.ts`），加载不了时每次都回 `nodirect`，手机直接走转发。
  - `bridge.ts`：通道里的流原样转给本机远程访问监听器 `127.0.0.1:<远程端口>`（socket 带 `cwRemote`，必须有设备令牌），**绝不**连 3090。配对通道只放行 `POST /api/pair`（其它 403「还没配对，只能先配对」）；设备通道只认这台设备自己的令牌（query 的 `token=` 和 `cw_token` cookie 都查，别的 403「这个令牌不是这台设备的」）。
  - 手机壳 `web/src/shell/`：Vite 第二个入口 `web/vite.shell.config.ts` → `web/dist-shell/`（index.html + 经典脚本 sw.js + 一个 JS 一个 CSS，约 85 KB，不进桌面安装包）。`main.ts` 画界面、拨号；`session.ts` 管一次连接（取界面文件、断了按 0 / 2 / 5 s 重拨、电脑换了版本就重开界面）；`sw.ts` + `route.ts`：壳自己的文件从预缓存给，`app/…` 从这台电脑这个版本的缓存给，没有的和 `app/api/…` 经 MessageChannel 交给拥有这个界面的壳窗口走通道（`forward.ts`；没有窗口 503、60 s 没回 504、顶层打开的 `app/api/…` 不带标记 403）；`tunnel.ts` 是 `window.__cwTunnel`，界面在 iframe 里由 `web/src/ws/tunnel.ts` 认出它，WebSocket 换成通道（这时界面不注册自己的 sw.js，也不提供「在新窗口打开当前分组」：`canOpenWindow()`，新窗口是没有通道的顶层页面）；`devices.ts` 存 IndexedDB `cw-shell`（设备记录带电脑的 broker / STUN 列表，见下）；`explain.ts` 是壳自己的「中文说明 + 原文」表，形状和 `@errors` 一样，但故意不合并（R12a）：它只解释通道和桥接的错误，`@errors` 讲的是供应商、server.log、代理，手机上都没有。
  - **一台手机配对的几台电脑互相看得到令牌**：每台电脑的界面都在壳的同源 iframe 里跑，IndexedDB（所有设备令牌）、localStorage、Cache Storage 共用；README 和 spec §8 写明「只把互相信任的电脑配到同一台手机上」，局域网配对没有这个问题。壳自己的缓存防篡改：构建把每个预缓存文件的 sha256 写进 `sw.js`（`__SHELL_HASHES__`，`./` 是页面本身），SW 从缓存给壳文件前用 `integrity.ts` 的 `verifiedShellFile()` 核对，对不上就删掉那条、走网络（网络的回答不核对）；不在表里的地址不读缓存。各台电脑的界面缓存 `cw-app-*` 不核对（内容来自电脑），所以在手机上删除一台设备时清掉**所有**电脑的界面缓存（`assets.ts` 的 `appCaches`），不只那一台的。
  - 界面 Vite `base: './'`，所有 `api/…`、`manifest.webmanifest`、`sw.js`、图标都是相对路径（`util/app-url.ts` 的 `appUrl()`，`app-url.test.ts` 扫源码），iframe 在 `app/index.html` 下才能用。
  - 设置 → 手机与其它电脑：「在外面也能用」开关、二维码默认「在哪都能用」（旁边切「只在局域网（不用联网）」）、「复制配对链接」、「不让电脑睡眠」、设备行的最近一次连接；「更多选项」（`AnywhereMore.tsx`）是 broker 列表、STUN 列表、手机页面地址、最近 20 次连接。MQTT / WebRTC / STUN / ICE 只出现在「更多选项」和 tooltip 里（`wording.test.ts` 和壳的 `explain.test.ts` 都有闸）。
- **频道与密钥**（HKDF-SHA256）：设备 `K = sha256(设备令牌)`，电脑本来只存这个哈希（`deviceRoomFromHash`），所以 `tokenHash` 现在是密钥材料，诊断包的 `maskSecrets` 打码它；配对 `K = P`（二维码里一次性的 16 字节）。salt 设备 `cw-anywhere-v1` / 配对 `cw-pair-v1`，info `topic` → 频道 `cw1/<32 位 hex>`，`signal` → AES-256-GCM 牵线密钥；转发密钥 = HKDF(K, 手机随机数 ‖ 电脑随机数, `relay`)，每次拨号一把新的，IV 带方向字节。信封 AAD = 频道名，时间差 > 5 分钟或随机数见过（LRU 2048）丢掉。二维码 `<shellUrl>#p=<base64url({v:1, ps, code, pc, b?, st?})>`（`b` / `st` 只在电脑的列表不是默认时出现，见下），`#` 后面不发给任何服务器。
- **默认列表**（`core/lists.ts`，`core/index.ts` 导出）：牵线 broker 五个（emqx、emqx-cn、mosquitto、shiftr、hivemq），转发只用标了 `relay` 的 mosquitto / shiftr / hivemq（emqx 突发会限流，实测收回一半）；STUN 五个（cloudflare、hitv、miwifi、bilibili、google）。设置里能整表替换：条目怎么算合法、每张表最多 16 条（`MAX_LIST_ENTRIES`）在 `core/lists.ts`，电脑（`brokerDefs()` / `stunList()`）、二维码、壳的 localStorage 覆盖、ICE 配置（`rtcConfig()`）用的都是它；设置页的编辑器另外只收 `wss://`（手机页面的 CSP 只放行它），而且至少一行勾「用于转发」（转发要两边都有）。`CW_NO_PUBLIC_BROKERS=1`（e2e、ui-smoke、单测）时没有默认 broker，只连测试自己配的。
  - **手机经二维码拿到电脑的列表**（F2）：`pairLink()` 在电脑的列表和默认不同时往 JSON 里加 `b` / `st`（`pairLists()`，`v` 仍是 1），壳 `parsePairLink()` 用同一套规则读，字段在但读不出能用的条目（`st: []` 除外）就是 `BAD_LISTS`「这个配对链接里的服务器列表读不出来」，不退回默认。配对用链接的列表，`DeviceRec.brokers / stun` 存下，之后拨这台电脑都用它们（`override.ts` 的 `dialLists()`：localStorage 覆盖 > 记录 > 默认；壳一次只拨一台电脑，`main.ts` 按列表换一个 `Brokers`）。改了列表 / STUN / 端口：设置页清掉屏幕上的二维码（配对房间随 `refresh()` 没了），保存时提示已配对的手机要重新扫码。整条链接（最坏情况：电脑名 64 个三字节字符）不能超过 `MAX_PAIR_LINK_BYTES`（2 900，一个 40-L 二维码装 2 953 字节），编辑器保存前用 `pairLinkBytes()` 检查；`settings/pair-qr.ts` 装不下 M 级时降到 L 级、码密时显示得更大，`pair-qr.test.ts` 编码最长的合法链接。
  - **broker 重连退避**（F5）：断了 / 连不上 15 s 后重连，接着失败每次翻倍、最多 5 分钟（`redialDelay()`），连上一次或 `stop()` 后从 15 s 重算。
  - **手机换网络**（F4）：`online` 时壳调 `Session.networkChanged()`，页面回到前台时调 `Session.pageShown()`：两个都是正在用慢速转发就立刻 `brokers.stop(); start()`（订阅保留，转发靠重传接着用，不用等 30 s 无响应），断着就重拨。上一条是慢速转发、60 s 内没有 `online` 时，重拨只给 ICE `RELAY_AGAIN_ICE_MS`（4 s，`core/dial.ts`）。**回到前台不算网络变化**：手机放下超过 30 s 再拿起来，转发正好因为 30 s 没声音被判死，这时要的是 4 s 的短窗口；算成网络变化就要等满 20 s ICE（终审复查抓到的）。broker 重连退避（15 s 起翻倍、封顶 5 分钟）只在一条连接**稳定 60 s**（`REDIAL_STABLE_MS`）后断开才从头算：连上就踢人的 broker 照样翻倍。
- **限制**：转发每条有效载荷 ≤ 12 288 字节、每边每秒 ≤ 20 条（小帧打包成 BATCH）、窗口 32、1.5 s 没确认重传；在转发上 `/api/file`、`/api/attachments` 一律 413「慢速转发时不能预览 / 上传文件」（壳把 413 正文显示在顶上的条里），单个响应先在电脑上收完、超过 2 MiB 就 413「慢速转发时单个响应不能超过 2 MB」，每条通道同时最多攒 4 个响应、60 s 收不到数据就失败。界面首屏入口文件现在约 1.5 MB：换了版本又只能走转发时要经转发取它，每个入口文件必须 < 1 900 000 字节（`MAX_ENTRY_BYTES`），超了在转发下就打不开新版本（壳说「慢速转发有大小限制…」）。壳的构建（`npm run build -w web` 的第二步）检查 `web/dist`，超了直接失败；`shell/assets.test.ts` 同样检查，但 CI 先测后构建，那条只在本地有 dist 时跑。
- **iOS**（R12b）：主屏幕图标打开的网页和 Safari 的存储是分开的。Safari 里带 `#p=` 打开时先问「先添加到主屏幕（推荐）/ 就在 Safari 里用」，链接留在地址里给主屏幕书签用；主屏幕里也能「粘贴配对链接」。主屏幕图标每次都打开保存时的地址（`#p=` 一起），所以壳在 localStorage `cw.shell.pairLinks` 里记着试过的链接（配对密钥哈希的前 12 字节，不存密钥本身）：用过的只显示列表，10 分钟前第一次见的说过期。`#p=` 能不能跟着「添加到主屏幕」留下来还没在真 iPhone 上验证。
- **不让电脑睡眠**：`remote.keepAwake`（缺省开）+ 远程访问开着 → server `remote/keep-awake.ts` 经 `parentPort` 告诉桌面壳，`desktop/src/keep-awake.ts` 用 `powerSaveBlocker('prevent-app-suspension')`（两边各一份同样的规则，测试钉住它们相同）。屏幕照样关、合盖照样睡；网页版只给一句提示。
- **壳放在哪**（R12d，用户 2026-10-02 决定）：一个账号的所有 GitHub Pages 共用 `<用户>.github.io` 这一个 origin，IndexedDB 里的设备令牌、Cache Storage、Service Worker 作用域都会和同账号的其它页面（比如 `site/` 的介绍页）混在一起。所以壳放在一个专门的 GitHub 组织的站点根目录：组织 `claude-web-shell`，仓库 `claude-web-shell/claude-web-shell.github.io`，地址 `https://claude-web-shell.github.io/`（2026-10-02 建好）。本仓库的 `.github/workflows/pages.yml` 只在 tag 时构建、上传 artifact，不部署；部署由那个站点仓库自己跑 `deploy/shell-site/.github/workflows/deploy.yml`（按 tag 拉本仓库构建，`version.txt` 和线上一样就跳过，每天看一次新发布；action 固定在提交 SHA 上，Pages 写权限只给发布那一个 job），一次性步骤在 `deploy/shell-site/README.md`。手机页面因此有两个信任根：组织的成员，和本仓库的发布权限 + 构建依赖（每天的运行自动发布 `releases/latest`，中间没有人看；README 的风险说明写了，自己部署的人可以去掉 `schedule` 手动发 tag）。每天的定时触发在站点仓库 60 天没有活动后被 GitHub 暂停（要去 Actions 里重新打开）；本仓库的发布在 `web/package.json` 里没有 `build:shell`（手机页面之前的版本）时检查那一步直接跳过，不构建、不报错。缺省地址只有 `server/src/remote/anywhere/service.ts` 的 `DEFAULT_SHELL_URL` 一处（设置页的显示取自 `remote.status`），设置里可改。壳在根目录 `/` 下也能用（`route.test.ts` 有根作用域的用例）。
- **打包**：node-datachannel 在根 package.json 的依赖里，`asarUnpack` 两条（`node-datachannel/**`、`@node-datachannel/**`），`smoke-packaged` 检查它能从 `app.asar.unpacked` 加载。
- **调试**：
  - `node server/ws-phase21.mjs`（e2e 默认列表里，自己起 server）：两个本地 broker（一个只牵线、一个 `dropEvery: 7` 并承担转发），手机由 `server/dist/remote/anywhere/core` + node-datachannel 扮演：配对、`sessions.list`、`/api/file` Range、附件上传、强制转发（丢包下每个回答都完整，413）、吊销后 2 s 内断开。server 的代理是一个记录器，见到任何请求都算失败。只用一个丢包 broker 不行：hello / offer / answer 只发一次，丢了拨号就失败。
  - `node scripts/shell-smoke.cjs [--show] [--keep]`（先 `npm run build:all`，约 30 s）：本地静态服务把 `web/dist-shell` 放在根目录（CSP 临时加上 `ws://127.0.0.1:*`，`sw.js` 里页面的 sha256 换成改过 CSP 的那份，构建产物不改），Electron 里真跑壳：不设 localStorage 覆盖，扫码链接（带电脑自己的 broker、空 STUN 列表）配对、设备记录存下列表、iframe 里的界面经通道连上（`sessions.list` 有种下的对话）、`app/api/file` 的图片能显示；然后用 preload 让 ICE 失败（`localStorage['smoke.noDirect']` → `iceTransportPolicy: 'relay'` 且没有 TURN），壳按记录里的列表改走慢速转发、界面照样连上、图片被拒且顶上的条显示 413 正文；断网（`enableNetworkEmulation({offline})`）后壳从预缓存打开；改写 Cache Storage 里壳的 JS 后重开，SW 不用它（页面跑的是站点上的那份，那条缓存被删）；最后设上覆盖，console 有一行 info。任何 console 错误 / 警告都算失败；Electron 和 server 的代理都指向记录器，页面建的每个 RTCPeerConnection 都没有 ICE 服务器。Electron 的 `console-message` 对同源子 frame 报的是主 frame，分辨靠脚本 URL。
  - mock broker `server/src/remote/anywhere/__mocks__/mqtt-broker.mjs`（纯 JS，脚本直接 import）：`dropEvery`、`frameBytes`、`auth`、`denyTopics`、`ignorePing`、`silent`，`droppedTopics` 看丢的是哪条。
  - 壳的 localStorage 覆盖（`web/src/shell/override.ts`，只给测试和懂的人，优先于二维码 / 设备记录里电脑自己的列表）：`cw.shell.brokers`（BrokerDef 的 JSON 列表，只认 `ws:` / `wss:`）、`cw.shell.stun`（JSON 字符串列表，只认 `stun:` / `stuns:`，空列表 = 不用 STUN），条目规则和电脑的设置是同一份（`core/lists.ts`）。只有键不存在才用默认；键在但读不出来（不是 JSON、不是列表、一条合法的都没有）一律当空列表（测试写错了也不会连到公共 broker）。用了覆盖时壳的 console 打一行 info「[shell] 使用 localStorage 里的自定义列表：…」，shell-smoke 检查它出现。正式的 CSP 只放行 `wss:`，`ws://` 的 broker 只在 CSP 放行它的地方能用。
